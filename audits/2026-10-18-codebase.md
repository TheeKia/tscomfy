- **supported:** strong evidence, with the limits stated.

## 3. Finding details

### F-001: `--url` with credentials fails under Node and prints the password and query token
- **Location:** `packages/cli/src/io.ts:46` (`systemIo().fetchText`: `fetch(url, …)`) and `io.ts:62` (`Could not reach ${shown}: ${reason(error)}`).
- **Trigger:** the installed bin (`#!/usr/bin/env node`) with a `--url` that has userinfo.
- **Expected:** plan §9, the CLI guide and the usage text say credentials are supported and "never written or shown".
- **Actual:** Node's `fetch` refuses URLs with userinfo, and its error message contains the full URL. The redacted `shown` prefix is followed by the raw message, so the secret is printed. Reproduced under Node 26.11.1:

  ```
  $ node --conditions=@tscomfy/source packages/cli/src/main.ts generate --url 'http://user:hunter2@127.0.0.1:9/?token=SECRET' --out ./cred
  tscomfy: Could not reach http://127.0.0.1:9/object_info: Request cannot be constructed from a URL that includes credentials: http://user:hunter2@127.0.0.1:9/object_info?token=SECRET
  ```

  Bun turns userinfo into Basic auth, so `system.test.ts` passes. The Node tests and `test:pack` only use `--from`.
- **Repair direction:**
  - Remove the userinfo and send an `Authorization: Basic …` header yourself.
  - Never put a raw `fetch` error message into a `CliError` without redacting it.
  - Add a `--url` test under Node with credentials, against a local stub server.

### F-002: `toUi` writes invalid JSON when a left-out input is named after an `Object.prototype` member
- **Location:** `packages/core/src/ui/export.ts`, `UiWriter`. Unguarded reads `inputs[...]` at `:217-220` (`chosen`), `:249` (`#slots`) and `:285` (`#savedWidgets`).
- **Cause:** `inputs` is the exporter's prompt node inputs, a normal-prototype object.
- **Trigger:** a schema with optional inputs named `valueOf` and `constructor`, left out.
- **Actual (reproduced):**
  - `stringify(toUi(wf).workflow)` contains `"widgets_values":[3,,],"widgets_values_named":{"a":3,"valueOf":undefined,"constructor":undefined}`.
  - `importUi` of that text gives `E_INVALID_JSON`. No diagnostic is raised along the way.
  - A dynamic combo named `toString` that is left out would read a function as its choice.
- **Expected:** valid UI JSON. Prototype-named inputs already work through `toApi`, `validateApi` and the importers, which guard with `Object.hasOwn`.
- **Repair:** use `Object.hasOwn` for every `inputs[...]` read in `UiWriter`, or build exporter inputs with a null prototype. Add a prototype-named-input case to the UI export tests.

### F-003: The CLI prints server-controlled strings unescaped
- **Locations:**
  - `packages/cli/src/report.ts:42` (`formatDiagnostic`) and the pack names printed in `reportDiagnostics`.
  - `packages/cli/src/check.ts`: `listed()` and `formatChange`, which print class, input and option names.
  - `packages/cli/src/generate.ts:104`: the `(ComfyUI ${comfyVersion})` text, where the version comes from `/system_stats`.
- **Evidence:**
  - A mock class named `Evil\e[2J\e[31mNode`, with `python_module` `custom_nodes.\e]0;pwned\apack`, prints raw escape sequences. Seen through `cat -v`: `custom_nodes.^[]0;pwned^Gpack: 2` and `W_INVALID_INPUT_SPEC Evil^[[2J^[[31mNode › …`.
  - The CLI already escapes control characters in `errorBodyMessage` (`util.ts:51`) "so none reaches the terminal". The policy is applied in one place only.
- **Impact:** any installed custom node pack can clear the screen, recolor output or set the terminal title during `generate` and `check`.
- **Repair:** one `printable()` helper (C0, DEL, C1, bidi controls) applied to every server-derived string the CLI prints.

### F-004: Codegen's display-width table disagrees with oxfmt for emoji
- **Location:** `packages/codegen/src/doc.ts:207-289` (`textWidth`, `WIDE_RANGES`). The comment at `:221` claims Unicode 15 emoji presentation.
- **Invariant broken:** generated output must already be oxfmt-formatted (AGENTS.md, plan §9).
- **Evidence:** I generated combo options with emoji near column 100 and ran oxfmt over them (`printWidth: 100`):
  - `⚙️` (U+2699 U+FE0F) and `❤️`: we count 1 column, oxfmt counts 2, so oxfmt breaks lines we keep on one.
  - `👨‍👩‍👧` (ZWJ sequence): we add up each emoji, oxfmt counts the sequence once, so we break lines oxfmt keeps.
  - `🖼` (U+1F5BC, text presentation): we count 2, oxfmt counts 1.
  - Result: 28 differing lines out of 44 cases.
  - The codegen reviewer swept about 12.5k code points and found 406 differing lines, including U+2630-2637, U+4DC0-4DFF and skin-tone modifiers.
  - `format.test.ts` covers only a few wide characters.
- **Impact:**
  - Custom node packs use emoji in names and options.
  - If a user formats the generated directory, `tscomfy check` then reports the files as edited.
  - The repo's own `format:check` would fail on such a fixture.
- **Repair:** match oxfmt's width algorithm, including grapheme clusters, VS16 making a sequence wide, and ZWJ sequences counting once. Add a code-point sweep and common emoji sequences, compared against oxfmt, as a test.

### F-005: `accepts()` returns `true` for a MatchType output into a dynamic combo
- **Location:** `packages/core/src/schema/accepts.ts:21`. The line `if (output.matchTemplate !== undefined) return true;` runs before the dispatch on input kind.
- **Expected:** the JSDoc (`:13-16`) says a dynamic combo answers `false` "whatever the output", and `acceptsType` returns `false` for `dynamicCombo` (`:50-53`).
- **Actual:**
  - A MatchType output into a `dynamicCombo` input gives `true`.
  - MatchType outputs are already typed `any` (`object-info/outputs.ts:69`), so line 21 changes the result only in this case.
  - No internal caller is affected, because validation uses `acceptsType`. It is a public predicate that answers looser than its contract and than the soundness ordering allows.
- **Also:** the JSDoc at `:8-9` says "a legacy combo only takes an identical option list". The tests (`accepts-cases.ts`) also accept `*` and MatchType outputs into one.
- **Repair:** delete line 21. Add a dynamic-combo × MatchType case to `accepts-cases.ts`. Fix the legacy-combo sentence.

### F-006: `importUi` throws `TypeError` on an id collision
- **Location:**
  - The ids are emitted by `packages/core/src/ui/import/emit.ts` (`nodeKey`).
  - The throw is in `packages/core/src/graph/workflow.ts:117-118` (`GraphBuilder.assemble`).
- **Trigger:** a root node with id `"40:31"`, plus a subgraph instance `40` whose inner node is `31`. Reproduced: `TypeError: workflow: node id "40:31" is empty or taken`.
- **Expected:** errors are data. A malformed or hand-edited file should produce diagnostics, as the guides promise for every function that reads data.
- **Repair:** detect duplicate emitted keys before `assemble`. Keep one node, following the frontend's object-assignment order, and report a diagnostic (e.g. `E_INVALID_WORKFLOW`).

### F-007: The release job grants `id-token: write` to every step
- **Location:** `.github/workflows/release.yml:9-11` (workflow-level `permissions`) and its single `publish` job.
- **Impact:**
  - Every tool that runs during `bun run check` and `test:pack` (tsc, oxlint, oxfmt, npm, test code) can mint the OIDC token that trusted publishing accepts.
  - The risk is reduced by exact versions and a frozen lockfile. Not verified against a live run.
- **Repair:**
  - Split into a build/test job with `contents: read` that uploads the tarballs.
  - Add a publish job that `needs:` it and holds `id-token: write`.
  - Consider pinning actions by SHA.

### F-008: getting-started says `seed` is required

- **Evidence:** KSampler's `seed` has `default: 0`. The generated type is `readonly seed?: …`. By plan §7.2, any input with a default is optional.
- **Why it matters:** this is the first guide users read.
- **Repair:** change the comment to `/* missing: sampler_name, scheduler */`.

### F-009: ADR-0005 says releases use `bun publish`
- **Location:** `docs/decisions/0005-zero-runtime-dependencies.md:16`.
- **Evidence:** `release.yml` runs `bun pm pack` and then `npm publish <tgz>`. ADR-0001, ADR-0012 and CONTRIBUTING all describe it that way.
- **Repair:** "Releases pack with `bun pm pack`, which rewrites `workspace:` ranges, and publish the tarballs with npm (ADR-0012)."

### F-010: `importUi` throws, or allocates without bound, on a huge `widgets_values.length`
- **Location:** `packages/core/src/ui/import/widget-values.ts:279-287` (`positionalValues`: `Array.from({ length: Math.max(0, Math.floor(length)) })`).
- **Trigger:** `"widgets_values": {"length": 1e10}` gives `RangeError: Array length must be a positive integer of safe magnitude`. Reproduced. A large but valid length, such as 5e7, allocates that many slots.
- **Repair:** cap the length at the number of widgets or own index keys, or treat an implausible `length` as named values.

### F-011: `validateApi` throws `RangeError` for a non-finite INT
- **Location:** `packages/core/src/validate/validate-api.ts:652-658` (`compareMixed`: `BigInt(Math.floor(value))`), reached from `#constant` → `range` (`:218-228`).
- **Trigger:** `validateApi({ "1": { class_type: "KSampler", inputs: { seed: NaN } } }, schema)` throws `RangeError: Not an integer`, and so does `Infinity` (reproduced). The `validateApi` JSDoc (`:44`) says malformed input is reported, never thrown.
- **Related:** `steps: NaN`, which has number bounds, only gets `W_NON_INTEGER_VALUE`, a warning. The builder already rejects NaN with a `TypeError`, so this is reachable only through a hand-built prompt.
- **Repair:** report non-finite `int` and `float` values as `E_INVALID_VALUE` in `#constant` before checking the range.

### F-012: An over-range bigint passes an unbounded FLOAT
- **Location:** `validate-api.ts:230-235` (`case "float"` accepts any bigint).
- **Trigger:** a 400-digit integer literal in a FLOAT input that has no `max`. `parse` reads it as a bigint, and `validateApi` returns no diagnostics.
- **Backend behavior:** Python's `float(int('9'*400))` raises `OverflowError`, which the backend reports as `invalid_input_type`. This breaks the soundness ordering, but only for an absurd input.
- **Repair:** reject a bigint whose magnitude exceeds `Number.MAX_VALUE`.

### F-013: The bypass/mute fallback fills the default of an optional widget the frontend never sends
- **Location:** `packages/core/src/api/modes.ts:279-304` (`widgetValue`).
- **Cause:** it checks `sendsValue` only for `kind === "value"`. The exporter gates on `sendsInputValue(input)` (`frontend/widgets.ts:117`), which also returns false for an optional primitive whose `widgetType` is never sent (for example `CAMERA_ANGLE_VIEW`).
- **Effect:** left unlinked, such an input is omitted. Linked to a bypassed node that has no matching input, it is exported with its default, and `W_LINK_DROPPED` says the widget's value is sent.
- **Impact:** parity only. The backend accepts the extra optional key.
- **Repair:** call `sendsInputValue(input)` in `widgetValue`; better, fix F-031.

### F-014: `toUi` drops dangling links silently
- **Location:** `packages/core/src/ui/export.ts:415-416` (`#link` returns `null` when the origin isn't in the workflow) and `:347` (`#lostInputs` skips every link).
- **Trigger:** `importApi` of a prompt with `"clip": ["9", 1]` and no node 9, then `toUi`. Both report no diagnostics and no link is written. Reproduced.
- **Effect:** the frontend's prompt then lacks `clip` while `toApi` sends `["9",1]`. This contradicts the `toUi` contract that every difference is reported.
- **Repair:** report `W_UI_VALUE_LOST`, or a dedicated code, for each dropped link.

### F-015: `%Node.widget%` is expanded from an already-replaced value
- **Location:** `packages/core/src/ui/import/primitives.ts:67-80` (`replaceFileNames`). It writes replaced text back into `graph.values`, and `TextReplacer.#widgetValue` (`:182-200`) reads those values for later save nodes.
- **Frontend behavior:** it serializes `applyTextReplacements(widget.value)` without changing `widget.value`, so a reference to another save node's `filename_prefix` sees the raw `%…%` text.
- **Our behavior:** the result depends on file order. Checked against frontend 1.55 source maps, not against the live frontend.
- **Repair:** compute every replacement from the values before any replacement, then write them.

### F-016: Autogrow slot types get parentheses oxfmt strips
- **Location:** `packages/codegen/src/emit-types.ts:545-546` (`#autogrow`), used at `:560` and in `#repeated` (`:668`).
- **Evidence (reproduced):** an Autogrow template typed `COMBO` emits `readonly a1: (In<"COMBO"> | Out<OptionList>);` and `readonly [(…), ...(…)[]]`. oxfmt rewrites these to `readonly a1: In<"COMBO"> | Out<OptionList>;` and `[In<"COMBO"> | Out<OptionList>, ...(…)[]]`. No mock covers a multi-atom template.
- **Repair:** add parentheses only in array-element position.

### F-017: Numeric combo literals are emitted as `1e+21`
- **Location:** `emit-types.ts:749-751` (`literal()` uses `String(option)`).
- **Effect:** oxfmt rewrites `1e+21` to `1e21`.
- **Repair:** use `expressions.ts` `numberText`, which already handles this.

### F-018: Transpiler typing and the emitted types disagree on bare dynamic-combo keys
- **Location:** `packages/codegen/src/typing.ts:124-132`. It requires every option input to be optional. The emitted types (`emit-types.ts:366-384`, `:612`) only count inputs where `sendsInputValue` is true.
- **Trigger:** an option whose only required input is a display-only widget. `{mode:"preview"}` is transpiled to `raw(…)` with a spurious `W_TRANSPILED_AS_RAW`, but `n.D({ mode: "preview" })` compiles.
- **Repair:** one "may all be left out" rule in `rules.ts`, used by both.

### F-019: Server text can inject JSDoc tags
- **Location:** `packages/codegen/src/names.ts:33-35` (`commentLines`), used by `emit-types.ts:821-832`.
- **Evidence:** a tooltip line `@deprecated really` is emitted as ` * @deprecated really`, so editors strike the input through. Any `@tag` or `{@link}` at the start of a line works the same way. The local corpus has no such case.
- **Repair:** escape a leading `@` and `{@` in server text.

### F-020: Header `//` lines escape `*/`
- **Location:** `packages/codegen/src/names.ts:43-45`. `headerLines` uses `commentText`, which turns `*/` into `*\/`. That escape is only needed in block comments.
- **Effect:** a `--out src/*/x` path is recorded as `src/*\/x` in "Regenerate with:".
- **Impact:** only the human-readable header. `check` uses the manifest.
- **Repair:** only flatten line terminators for `//` lines.

### F-021: The CLI's unrecordable-value check is incomplete
- **Location:** `packages/cli/src/args.ts:55-56`. The check matches `[\u0000-\u001f\u007f]` only.
- **Evidence:**
  - `--out "ls<U+2028>x"` is accepted. Codegen's `commentText` turns the U+2028 into a space, so the header records `--out 'ls x'`, and re-running that command writes elsewhere.
  - U+2029 and C1 controls are also accepted.
  - The server's `comfyui_version` is stored in the manifest and later shown as `--comfy-version '<raw>'` without this check.
- **Repair:**
  - Refuse every character that `commentText` rewrites.
  - Drop or refuse a server version that holds one.

### F-022: `check --from <other file>` suggests the wrong version
- **Location:** `packages/cli/src/check.ts:114-116`. The condition `flags.has("from") && manifest.comfyVersion !== undefined` attaches the recorded version to any `--from` file.
- **Contrast:** `generate`'s `withSnapshotVersion` (`generate.ts:121-131`) keeps the version only when the file is exactly the recorded snapshot. In the drift case, the file differs from the snapshot by definition.
- **Repair:** share `withSnapshotVersion`'s rule.

### F-023: `typedSchema` deep-freezes the caller's node definitions
- **Location:** `packages/core/src/schema/typed.ts:117-125`. It copies the top level and `nodes`, then `freezeSchema` deep-freezes the shared `NodeDef`s in place.
- **Evidence:** reproduced: the caller's `def` is frozen afterwards. The JSDoc doesn't say so.
- **Repair:** document the side effect, or deep-copy.

### F-024: `stringify` writes invalid JSON for `undefined` members and holes
- **Location:** `packages/core/src/json/stringify.ts:16-30`.
- **Evidence:** `stringify({a: undefined})` gives `{"a":undefined}`, and `stringify([1,,2])` gives `[1,,2]`.
- **Contract:** the JSDoc says the output is what `JSON.stringify` writes, and the function throws `TypeError` for other misuse.
- **Reachability:** only through type holes, such as a consumer without `exactOptionalPropertyTypes`. F-002 is one route.
- **Repair:** throw `TypeError` for `undefined` values and holes.

### F-025: The normalizer doesn't enforce the Autogrow template and DynamicGroup field rules it documents
- **Location:**
  - `packages/core/src/object-info/spec-reader.ts:270-329` (`autogrow`) and `:397-406` (`dynamicGroup`).
  - `object-info/inputs.ts:201-203`, where the legacy branch runs before `forceSocket`.
- **What is promised:**
  - `AutogrowInput.template` is "always link-only" (`schema/types.ts:180`, plan §9).
  - `forceInput` fields make a group `unknown` (`docs/diagnostics.md:31`).
- **Evidence (probed):**
  - A legacy-combo or DynamicCombo Autogrow template comes through as `combo` or `dynamicCombo`, and `validateApi` accepts a value for it.
  - A `[["a","b"],{forceInput:true}]` group field passes.
- **Impact:** the backend asserts these cases away, so only hand-made dumps reach them.
- **Repair:** in `autogrow()`, return `#invalid` for a template that isn't a socket or MatchType, and reject `forceInput` fields in `dynamicGroup()`.

### F-026: Transpiler destructuring claims names it then discards
- **Location:** `packages/codegen/src/transpile.ts:315-326` (`#statement`). Names are claimed before the width check. When the pattern is too wide, the code falls back to `name[i]` and the claimed names are never declared.
- **Evidence:** the output contains `const aRatherLongOutputNameNumberOne2 = …` with no `…One` declared anywhere.

## 4. Open concerns and product questions

### Q-001: Should raw nodes get a schema default when a link resolves to nothing?
- `api/export.ts:88` passes the definition of a raw node to `applyModes`, which then fills `widgetValue`.
- Probed: `raw("K", { steps: mutedRef })` exports `"steps": 20`, while other defaults are not filled.
- The guide and plan §7.1 say raw inputs are sent as given, with no defaults. The fallback does mirror the frontend for a real node of that class.
- **Decision:** skip the fallback for `node.raw`, or document the exception.

### Q-002: How should a value given for a display-only or never-sent widget be handled?
- Today the exporter passes it through, validation is silent, and `importApi` downgrades the whole node to raw (F-040).
- **Options:**
  - Fold such keys structurally. The exporter puts them back at the same position, and the transpiler already falls back to `raw` when the types reject them.
  - Keep the raw downgrade with a truthful reason.
  - Add a validation warning.
- Each option needs a design decision and an ADR note.

### Q-003: Would a prerelease tag (`v0.2.0-rc.1`) publish under the `latest` dist-tag?
- `release.yml` runs `npm publish` with no `--tag`.
- **To resolve:** check npm's current behavior for prerelease versions without `--tag`.
