# ADR-0001: Bun as package manager, workspace tool, test runner and script runner

Status: accepted, 2026-10-17; amended 2026-10-18 (the CLI runs on Node too)

## Context

We need a package manager with workspaces, a test runner with snapshots, and a way to run TypeScript scripts without a build step. Using one tool for all of these keeps the setup small.

The published packages are a different matter: users install them with whatever they use, and `npx @tscomfy/cli` runs the `tscomfy` bin with Node. The first CLI used `Bun.file`, `Bun.write` and `Bun.CryptoHasher` and a `#!/usr/bin/env bun` shebang, so under Node it failed with `ReferenceError: Bun is not defined`.

## Decision

Use Bun 1.4 (`packageManager: bun@1.4.3`) to develop: workspaces use Bun's default isolated linker and text `bun.lock`, tests use `bun test`, and scripts run with `bun`. Publishing uses `bun publish`, which rewrites `workspace:` ranges (npm leaves them as they are).

No published package uses Bun's APIs. The libraries use no runtime API at all (ADR-0003). The CLI uses only what Node and Bun both implement: `node:fs/promises`, `node:crypto`, `node:path`, `fetch` and `process`, with a `#!/usr/bin/env node` shebang. Its build config has `types: ["node"]` (`@types/node` 24, the oldest Node it supports) instead of Bun's types, so a `Bun` global in its source fails to compile.

## Consequences

- One tool replaces npm/pnpm, vitest/jest and tsx for development.
- Bun does not resolve workspace packages to source on its own, and has no bunfig setting for export conditions, so scripts pass `--conditions=@tscomfy/source` (ADR-0004).
- Only declared dependencies are linked into a package, which keeps the dependency rules in docs/plan.md §4 honest.
- The CLI runs on Node 24 or later and on Bun 1.4 or later (its `engines`). Two Bun behaviors it relied on are kept by hand: `Bun.file().text()` drops a UTF-8 byte order mark, as `TextDecoder` does (`readFile` with `"utf8"` keeps it, and `JSON.parse` then fails), and `Bun.write` creates missing directories, which `writeText` now does with `mkdir({ recursive: true })`.

## Evidence

Verified in docs/plan.md §16: workspaces with `workspace:*`, text lockfile, snapshot tests, conditions flag.

The Node CLI, verified 2026-10-18 with Node 24.22.0, Node 26.11.1 and Bun 1.4.3:
- `bun run test:pack` packs every package, installs the tarballs with `npm install --offline`, and runs the installed `tscomfy` bin (`--version`, `generate --from`, `check`, `transpile --prompt` and `--workflow`) under each Node, through its shebang, and under Bun; a consumer built with `tsc` then runs under each Node.
- `packages/cli/test/system.test.ts` runs the CLI's source under Node (which strips the types) and under Bun and compares the files they write, byte for byte.
- `Bun.file(path).text()` on a file starting with `EF BB BF` returns the text without U+FEFF; `readFile(path, "utf8")` returns it with U+FEFF; `new TextDecoder().decode(await readFile(path))` returns it without (Bun 1.4.3). A system test covers it.
- `npm publish --dry-run` (npm 12.2.1) of a package whose `bin` is `./dist/main.js` warns `"bin[x]" script name dist/main.js was invalid and removed`; with `dist/main.js` it keeps it. `npm pack` keeps `"workspace:^"` in the packed `package.json`; `bun pm pack` writes `^0.0.0`.
