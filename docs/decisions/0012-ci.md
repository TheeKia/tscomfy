# ADR-0012: CI runs the local gate and publishes releases

Status: accepted, 2026-10-17 as "No CI for now"; revised 2026-10-18

## Context

Until 0.1.0 the project had no CI: one developer, nothing published, and `bun run check` as the
single local gate. Publishing changes that. Users install the tarballs, so each release must
come from a known commit that passed the gate, and an npm token on a machine is a credential
that can leak.

## Decision

GitHub Actions, running the same scripts as local work:

- `.github/workflows/check.yml`, on pushes to `main` and on pull requests: `bun run check` (its
  CLI tests also run under Node, the oldest supported: 24), and `bun run test:pack` under Node 24
  and Node 26 (the CLI's supported range).
- `.github/workflows/release.yml`, on a `v<version>` tag, in two jobs. `build` checks that the
  tag matches every package's version, runs `check` and `test:pack`, and packs each package with
  `bun pm pack`, with read-only permissions. `publish` then publishes those tarballs in
  dependency order with npm **trusted publishing** (OIDC); it alone holds `id-token: write`, so
  no tool the checks run can mint a publishing token. Versions already on npm are skipped, so a
  release can be re-run; a prerelease goes out under the `next` dist-tag, not `latest`.

`bun run check` stays the gate for local work. `test:corpus` stays local, since the corpus is
real data that is never committed. Only a new package's first version is published by hand,
because npm configures a trusted publisher only for a package that exists.

## Consequences

- No npm token exists anywhere; npm attaches provenance to every release from the public
  repository.
- A passing CI run means exactly what a passing local `check` means: no second definition.
- Each package's trusted publisher on npmjs.com names `TheeKia/tscomfy` and `release.yml`, so
  renaming the workflow file breaks releases until they are updated.

## Evidence

User decisions, 2026-10-17 (no CI) and 2026-10-18 (CI and releases from CI, version 0.1.0).
Trusted publishing's requirements (npm 11.5.1+ and Node 22.14+, `id-token: write`, a matching
`repository.url`, an existing package) from docs.npmjs.com/trusted-publishers and
`npm help trust` (npm 12.2.1). Packing and a fresh npm consumer: plan §16, "Publishing".
