# The CLI

`tscomfy` (`@tscomfy/cli`) generates types from a server, checks them for drift, and transpiles
workflows into code. It runs on Node 24 or later and on Bun 1.4 or later. In this repository,
run it from source as `bun run tscomfy …`.

```
tscomfy generate (--url <server> | --from <object_info.json>) --out <dir> [options]
tscomfy check (--url <server> | --from <object_info.json>) --out <dir> [--verbose]
tscomfy transpile (--prompt <file> | --workflow <file>) --schema <dir> [options]
tscomfy help [<command>]    tscomfy --version
```

Every command takes `-h`/`--help`. Flags are `--flag value` or `--flag=value`; a value that starts
with `-` must use the second form (`--out=-weird`). Exit codes: **0** success, **1** a failure
or drift, **2** a usage error (the message and the command's usage go to stderr).

## generate

```sh
tscomfy generate --url http://127.0.0.1:8188 --out src/comfy/local
```

| Option | |
|---|---|
| `--url <server>` | The server. tscomfy sends only `GET /object_info` and `GET /system_stats` (for the ComfyUI version; optional), under the URL's path and with its query. Credentials (`http://user:pw@host`) and the query are sent but never written or shown. |
| `--from <file>` | A saved `/object_info` response instead of a server, such as the `object_info.json` a previous run wrote. |
| `--out <dir>` | The directory to write into. Created if needed. |
| `--name <identifier>` | The exported constant. Default: the directory name, camelCased (`my-server` → `myServer`). Names the transpiled modules need (`workflow`, `Workflow`, `NodesOf`, `n`, `raw`) and reserved words are refused. |
| `--import-extension .js\|.ts` | How `index.ts` imports `nodes.ts`. `.js` (default) for `tsc` and bundlers; `.ts` to run the sources directly with Bun. |
| `--comfy-version <version>` | With `--from`: the ComfyUI version to record. Default: the one recorded next to a snapshot `generate` wrote. |
| `--verbose` | List every diagnostic, rather than five per node pack. |
| `--quiet` | Print only errors, to stderr. |

It writes `nodes.ts`, `index.ts`, `object_info.json` (the response, byte for byte) and, last,
`tscomfy.json`, the manifest `check` and `transpile` read. Each file is replaced in one step, so
an interrupted run never leaves half a file. The file headers record the schema hash and the
command that regenerates them.

The report lists what was generated and the diagnostics, grouped by node pack. Warnings are
normal: `W_EMPTY_COMBO` for a loader with no files installed, server inconsistencies the
normalizer worked around. A response with no usable node (not JSON, an error body such as
`{"detail": "Not authenticated"}`, `{}`) exits 1 and writes nothing, so it can't replace good
types.

## check

```sh
tscomfy check --url http://127.0.0.1:8188 --out src/comfy/local
```

Exits 1 when the generated directory no longer matches the server, or doesn't match what
`generate` wrote:
- nodes added, removed or changed since the snapshot (inputs, combo options, outputs, details);
- a generated file that was edited, is missing, or comes from another tscomfy version.

It prints what changed and the `generate` command that updates the files. New files in upload
and remote combos (an image someone uploaded) are runtime state, not drift: they are mentioned
and ignored. Lists show the first ten names (five combo options); `--verbose` shows all. Run it
before a build to catch drift early.

## transpile

```sh
tscomfy transpile --workflow portrait.json --schema src/comfy/local --out src/portrait.ts
```

| Option | |
|---|---|
| `--prompt <file>` | An API-format prompt (the frontend's "Export (API)"). |
| `--workflow <file>` | A UI workflow (the frontend's "Save" or "Export"), read as the frontend would queue it. |
| `--schema <dir>` | The directory `generate` wrote. Types generated by another tscomfy version are refused: regenerate first. |
| `--out <file>` | Where to write the module; the schema is imported relative to it. Default: standard output, importing relative to the current directory. |
| `--name <identifier>` | The exported constant. Default: the file name, camelCased. |
| `--no-inline` | Give every node a variable, rather than inlining nodes used once. |

Diagnostics go to stderr; warnings don't change the exit code. A file of the other kind (a UI
workflow given to `--prompt`), a `POST /prompt` body, or a file with no readable node exits 1.
See [importing and transpiling](import-and-transpile.md) for what the code looks like.

## From code

`run(args, io)` runs the CLI in-process and resolves to the exit code; `systemIo()` is the real
file system, network and console, and a custom `Io` (for tests) throws `CliError` for expected
failures.

```ts
import { run, systemIo } from "@tscomfy/cli";

const code = await run(["check", "--url", "http://127.0.0.1:8188", "--out", "src/comfy/local"], systemIo());
```
