# Importing and transpiling

Most ComfyUI workflows start life in the frontend. tscomfy reads them back, as prompts or as
saved workflow files, and can write them out as typed code to keep working on.

## From a file to code

```sh
tscomfy transpile --workflow portrait.json --schema src/comfy/local --out src/portrait.ts
tscomfy transpile --prompt portrait-api.json --schema src/comfy/local --out src/portrait.ts
```

`--workflow` takes what the frontend saves ("Save", "Export"); `--prompt` takes "Export (API)".
The result is a module exporting the workflow, built with your generated types:

```ts
import { type NodesOf, type Workflow, workflow } from "@tscomfy/core";
import { local } from "./comfy/local/index.js";

export const portrait: Workflow<NodesOf<typeof local>> = workflow(local, ({ n }) => {
  const [model, clip, vae] = n.CheckpointLoaderSimple(
    { ckpt_name: "sd_xl_base_1.0.safetensors" },
    { id: "4" },
  );
  // …
});
```

Running it and exporting with `toApi` gives the same prompt back, for a prompt the frontend
wrote: node ids that aren't integers (`40:31`) may come back in another order, and what no
program can build (a cycle, a link to a missing node) is left out and reported. The code is formatted as oxfmt
(and Prettier) would format it, nodes come in dependency order, variables are named after the
outputs they hold (`latent`, `conditioning2`), a node used once is written inline at its use
(`--no-inline` turns that off), and inputs equal to their default are left out. Ids and titles
are kept, so the prompt stays comparable to the original; delete the `{ id }` options once you no
longer need that.

A node of a class your server doesn't have is written as `raw(…)` with its wire keys. So is a
node whose values the types would reject, reported as `W_TRANSPILED_AS_RAW`, so the output always
compiles. `transpile` refuses types generated by another tscomfy version: regenerate first.
See [the CLI reference](cli.md#transpile) for every option.

## In code

```ts
import { importApi, importUi, toApi } from "@tscomfy/core";
import { transpile } from "@tscomfy/codegen";
import { local } from "./comfy/local/index.js";

const fromPrompt = importApi(await Bun.file("portrait-api.json").text(), local);
const fromFile = importUi(await Bun.file("portrait.json").text(), local);

const { code, diagnostics } = transpile(fromFile.workflow, {
  name: "portrait",
  schemaModule: "./comfy/local/index.js",
  schemaName: "local",
});
```

Both importers take the file's **text**, not a parsed value, so seeds beyond 2^53 stay exact. They
return `{ workflow, diagnostics }` and never throw for bad input: a node they can't read is
reported and left out.

**`importApi`** reads an API prompt. Wire keys fold back into structured inputs by the schema
(`format.codec` into `{ option, inputs }`, `images.image0` into a list, `__value__` unwrapped). A
node of a class the schema lacks, or whose keys don't fold back (rows missing in a DynamicGroup,
keys under an unknown dynamic-combo option), is kept as a raw node with its wire keys
(`W_IMPORTED_AS_RAW`), so it still exports as it came. For prompts the frontend wrote,
`stringify(toApi(importApi(text, local).workflow))` gives back exactly `text`'s JSON, byte for
byte and key order included. Other prompts come back normalized: defaults filled in, `_meta`
added, keys in the frontend's order.

**`importUi`** reads a workflow file and builds the workflow **the frontend would queue for it**:
Reroutes and PrimitiveNodes are resolved, subgraphs are expanded (inner ids become `"40:31"`, as
in the frontend's prompts), Notes are dropped, links through bypassed and muted nodes follow the
frontend's rules, and `%Node.widget%` in save nodes' file names is replaced. Exporting the result
gives the prompt the frontend builds for the same file, checked against the frontend itself.
What it can't reproduce is reported: JavaScript of node packs that changes the prompt at queue
time, `%date:…%` (the queue time; kept as written, `W_QUEUE_TIME_VALUE`), legacy group nodes
(`E_LEGACY_GROUP_NODE`), and nodes of classes your server doesn't have, which stay raw.
[The UI format](ui-format.md) has the details.

Validation is separate from importing: `validate(imported.workflow)`, or `toApi`, which validates.
